About XerahS

The ShareX Team's experimental app. ShareX remains our flagship.

ShareX and XerahS

ShareX is our flagship product. It is a mature, dependable screen capture and file sharing tool for Windows, built over many years with help from its community.

XerahS is our experimental app, made by the same ShareX Team. It is where we try new technology, different approaches to the interface, and features that are not ready for ShareX, or may never suit it. Some ideas work out and some do not. XerahS is where we find out, so ShareX users don't have to.

Both apps are free and open source under the GPL v3, and both always will be.

Which one should I use?

  • Use ShareX if you are on Windows and want something stable that you can rely on every day.
  • Try XerahS if you are on Linux or macOS, or you want to try new ideas early and don't mind some rough edges.

XerahS is pre-1.0, and the three platforms are at different stages. On Windows it comes closest to ShareX. On macOS it is usable, with some packaging and colour issues still open. On Linux, screenshots are solid on X11 and Wayland, but screen recording is still being worked on. The platform status table in the README is kept up to date.

What we are experimenting with

One app on Windows, Linux and macOS

XerahS is built on .NET 10 and Avalonia UI, so the same app runs on all three desktops. Each platform still captures the screen with its own fastest native method: Desktop Duplication on Windows, ScreenCaptureKit on macOS, and the desktop portal on Wayland, plus X11 support.

Different approaches to the interface

  • Independent workflows. Each capture workflow has its own hotkey, tasks and settings, and none of them inherit from a hidden "default". There are no inheritance chains to untangle when something behaves unexpectedly.
  • A new image editor. Annotations are objects you can select, move, resize and restyle at any time. It has layers, more than 40 effects and GPU-accelerated rendering through Skia.
  • A video editor built on Omacut, a native Avalonia video trimmer.
  • Desktop-native capture on Linux, such as the OmaSnap capture engine and the omaxerahs command for the Omarchy (Hyprland) desktop.

Built for automation and AI agents

  • An MCP server that lets AI agents and editors capture, annotate, upload and search history through XerahS.
  • A command-line interface for scripts.
  • An optional assistant that works with the AI provider you set up in Settings.
  • Destination plugins, so new upload services can ship separately from the app.

Privacy before upload

Privacy mode finds sensitive data in a capture and lets you redact it before anything is uploaded.

Mobile

Native apps for Android (Kotlin) and iOS (Swift) that upload files and receive content shared from other apps, alongside earlier .NET MAUI and Avalonia mobile experiments.

How XerahS is built

XerahS is also an experiment in how software is made. It is developed with agentic coding: AI coding agents write much of the code, and the ShareX Team directs and reviews the work. To make that safe, the codebase is strict by design. Nullable checks are on, every compiler warning is treated as an error, and thousands of automated tests run before a change is accepted.

Larger changes start as public proposals. You can read them under Dev: XerahS Improvement Proposals, plus separate proposals for the image editor and the video editor.

If you would rather use software built the traditional way, ShareX is developed by hand and has years of community testing behind it.

What this means for ShareX

XerahS gives us room to experiment without putting ShareX's stability at risk. Ideas that prove themselves here can inform ShareX, but ShareX keeps its own pace and its own bar for stability. Trying something in XerahS does not mean it will come to ShareX.
